Appium Interview Primer

Overview
- What: Appium is an open-source mobile automation server for native, hybrid, and mobile web apps.
- Robot Integration: use AppiumLibrary (Robot Framework) to write readable tests that call Appium commands.

Prerequisites
- Languages/Tools: Java JDK (for Android emulator/tools), Node.js (for Appium server), Python, Robot Framework.
- SDKs: Android SDK / Xcode (macOS) for device/emulator.
- Python packages: install Robot + Appium libs:
  pip install robotframework Appium-Python-Client robotframework-appiumlibrary
  npm install -g appium
- Device: real device or Android emulator (start via `emulator -avd <name>`).

Environment Setup (Windows quick steps)
- Install Node.js and Java JDK.
- Install Appium server: `npm install -g appium` or use Appium Desktop.
- Ensure `adb` and `emulator` are on PATH (Android SDK platform-tools & emulator).
- Install Robot packages (see commands above).
- Verify Appium server: `appium --version` then start: `appium`.

Key Concepts to Know
- Desired Capabilities: platformName, deviceName, app, appPackage, appActivity, automationName.
- Session lifecycle: start session → find elements → interact → end session.
- Locators: id, xpath, accessibility_id, class, android=uiautomator, ios=predicate.
- Contexts: native vs webview (use Get Contexts, Switch To Context).
- Implicit/Explicit waits: prefer explicit waits (Robot keywords like Wait Until Element Is Visible).

Minimal Robot Example
- Save as `tests/user_appium_example.robot`

*** Settings ***
Library    AppiumLibrary

*** Variables ***
${REMOTE}    http://localhost:4723/wd/hub
${PLATFORM}  Android
${DEVICE}    emulator-5554
${APP_PACKAGE}    com.example.myapp
${APP_ACTIVITY}   .MainActivity

*** Test Cases ***
Open App And Click
    Open Application    ${REMOTE}    platformName=${PLATFORM}    deviceName=${DEVICE}    appPackage=${APP_PACKAGE}    appActivity=${APP_ACTIVITY}
    Wait Until Element Is Visible    accessibility_id=login_button    10s
    Click Element    accessibility_id=login_button
    [Teardown]    Close Application

Run From CLI
- From repo root (recommended):
  cd C:\Users\Admin\Desktop\learn_mcp_AI
  robot --pythonpath src tests/user_appium_example.robot

- With argument file:
  robot --pythonpath src --argumentfile tests/robot_args.txt tests/user_appium_example.robot

Common Robot/Appium Keywords
- Open Application, Close Application, Find Element, Click Element, Input Text, Get Text, Swipe, Tap, Get Contexts, Switch To Context.

Interview Q&A (brief answers)
- Q: What is Appium?: Mobile automation server supporting multiple languages and platforms.
- Q: How does Appium work?: Uses vendor automation frameworks (UiAutomator2, XCUITest) to drive apps via WebDriver protocol.
- Q: What are desired capabilities?: A map telling Appium which device/app/browser to automate.
- Q: How to locate elements?: id, accessibility id, xpath, UIAutomator/Predicate strategies.
- Q: Differences: native vs hybrid vs mobile web?: Native = platform app, hybrid = webview + native, mobile web = browser automation.
- Q: How to handle contexts?: Use Get Contexts then Switch To Context to toggle between native and webview.
- Q: How to wait for elements?: Use explicit waits (e.g., Wait Until Element Is Visible) rather than fixed sleeps.
- Q: How to run tests on CI?: Start Appium server in CI (or use cloud device farms), provide capabilities and run `robot` in pipeline.

Common Pitfalls
- Wrong appPackage/appActivity on Android.
- Missing automationName for specific behaviors.
- Expecting web selectors in native context (must switch context).
- Relying on fragile XPaths — prefer stable IDs/accessibility ids.

Cheat Sheet Commands
- Start Appium server:
  appium
- List devices:
  adb devices
- Start emulator:
  emulator -avd <AVD_NAME>
- Run Robot tests:
  robot --pythonpath src --outputdir results tests/user_appium_example.robot

Interview Preparation Tips
- Be ready to explain desired capabilities and show a short working example.
- Walk through debugging steps (adb logs, Appium server logs).
- Know locator strategies and when to use them.
- Practice writing one read-only test and one interaction test on an emulator.
